# Ресурсы, кэш и обновления
## Локальное хранение
В APK: движок, загрузчик, минимальный экран входа/ошибок, базовые шрифты и резервный UI. Цель: <=95 000 000 байт для выбранного распространяемого APK; финальную трактовку МБ и ABI фиксирует S01.
Данные загружаются в постоянный app-private files directory (Godot user:// после проверки платформенного пути), не в автоматически очищаемый Android cache directory.
Манифест связывает logical_id → sha256, size, content_type, bundle, dependencies. Файлы лежат по hash. Совпадающий hash не скачивается повторно.
Манифест/его ETag можно проверять при входе: это малый сетевой запрос, не загрузка всех ресурсов. Источник истины аккаунта всегда сервер.
Загрузка .part с возобновлением по Range/ETag, проверка размеров/hash, fsync по необходимости, атомарное переименование. Без поддержки Range загрузить файл заново с понятным сообщением. Поврежденный файл не активировать.
Перед загрузкой проверить место с запасом для старой и новой версии. Частично скачанное не считать готовым. Нет автоматического LRU/вытеснения скачанного актуального контента.
Ручная очистка по разделам показывает размер и необходимость повторной загрузки. Не удаляет учетные данные и не удаляет используемое в текущем бою.
Неизменившиеся ресурсы разделяются версиями. Заменяемые старые файлы освобождаются после снятия всех ссылок активных сессий; это замена устаревшего, не вытеснение актуального.
Удаление приложения, очистка данных Android или потеря устройства находятся вне гарантии хранения.

## Пакеты
bootstrap → tutorial → chapter_01 → районы/города → дополнительные режимы. "Скачать все" учитывает доступный каталог и фиксирует snapshot очереди. Обновления, появившиеся позже, идут отдельной понятной задачей.
Скачивание: размер, прогресс, пауза, повтор, ошибка, ограничения мобильного интернета на выбор. Пакеты распределять по нескольким небольшим файлам для точечного обновления.

## Активация
content_version, schema_version и required_capabilities проверяются до активации. Несовместимый клиент получает требование нового APK.
Не переключать контент во время боя или критического действия. Файлы и данные одного экрана не смешиваются из разных версий.
Обязательное обновление завершает безопасные операции, сохраняет состояние, возвращает на вход с объяснением.

## Обновление APK из GitHub
Настройки → "Проверить обновления". Подписанный манифест релиза: package_name, version_code, version_name, min_supported_version, abi, size, sha256, certificate_sha256, download_url и notes.
Использовать GitHub Releases https://github.com/maillunex-lang/UfaGame/releases и фиксированные versioned assets, например Game-arm64-v1.0.0.apk. Не полагаться на название latest для определения совместимости. Доступ через HTTPS, без GitHub-токена в клиенте.
Публичный ключ доверия в приложении, закрытый ключ манифеста вне репозитория; хеш из неподтвержденного файла сам по себе не подтверждает источник.
Загрузить с прогрессом, повтором/возобновлением; проверить hash, размер, package, versionCode и сертификат; затем передать установщику Android через ограниченный content URI/FileProvider или PackageInstaller.
Обработать отсутствие разрешения установки из этого источника, отказ пользователя, нехватку места, неподходящий ABI, неверную подпись. Никакой тихой установки.
Все версии одного package подписывать постоянным release-ключом; key backup отдельно и не публично. При потере ключа обновление поверх установленного APK может оказаться невозможно.
Для будущих магазинов предусмотреть отдельную стратегию обновления и проверить требования площадки при внедрении.
