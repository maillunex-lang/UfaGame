# Промпт продолжения в другом ИИ
Ты продолжаешь UfaGame: https://github.com/maillunex-lang/UfaGame .
Сначала прочитай актуальную передачу [docs/HANDOFF.md](docs/HANDOFF.md). Рабочая ветка: `codex/s10-studio-android`, не предполагай, что актуален default branch.
Не начинай заново и не считай этот комплект готовой игрой.

1. Получи актуальный checkout и прочитай AGENTS.md, PROJECT_SPEC.md, ARCHITECTURE.md, roadmap.md, OPEN_DECISIONS.md и VALIDATION_REPORT.md. Затем изучи файлы и историю git; при противоречии фактический код и проверки покажут степень готовности, а текущие решения владельца определяют требуемое поведение.
2. Кратко сообщи фактическое состояние: что реализовано/проверено, что только описано, какой commit/ветка, есть ли незакоммиченные изменения.
3. Выбери первый незавершенный этап с выполненными зависимостями и прочитай prompts/stages/Sxx.md. Если этап blocked, объясни конкретную недостающую вещь и продолжай независимую работу.
4. Выполни этап полностью в рамках критериев. При отсутствии версии инструмента проверь официальную документацию; секреты не ищи в публичном репозитории. Владелец выполняет все команды на VPS сам: передавай команды в чат, не проси SSH-доступ и не трогай чужие проекты.
5. Проведи проверки, зафиксируй команды, результаты и ограничения. Реальные деньги/покупки в тестовом окружении не использовать.
6. Отдельно обнови roadmap.md: статус, файлы, проверки, commit/путь отчета, незавершенное и следующий шаг. При изменении контракта обнови схемы/ADR/примеры.
7. Commit и push выполняй при доступе в разрешенный репозиторий без перезаписи чужих изменений. Не утверждай, что push/deploy/Android-проверка прошли, если доказательств нет.
8. В конце дай краткий результат, ссылку на commit при наличии и следующий шаг. Не отмечай целый этап done, если часть проверки недоступна.

Ключевые решения: APK <=95 МБ; 2D вертикальная RPG Башкортостана; 5 героев 2+3; ресурсы постоянные локальные, новые по hash; обновление APK из GitHub Releases с подтверждением Android; веб-комбайн и Android-оболочка; content-only ZIP готовых блоков; шаблонные жители 10–30 при малом живом онлайне, без инициативы при нуле; тестовые покупки сначала; roadmap обязателен после каждого этапа.
