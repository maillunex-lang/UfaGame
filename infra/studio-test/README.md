# Изолированный кандидат test stack

Подготовка для проверки S09, не выполненное развертывание S52. Содержит только
отдельные PostgreSQL/API и volume проекта Compose; host bind API только
127.0.0.1:8055, DB порт на host не публикуется. Имена контейнеров и volume
зависят от имени Compose проекта. Никогда не использовать чужой проект/volume.

Не запускать на VPS до завершения S51, проверки свободного порта и ресурсов,
тестирования конфигурации и плана резервирования. S52 зависит от S50/S51/S47/
S41/S44 и остается blocked: текущий стек не реализует эти этапы.

Пароль `S52_DB_PASSWORD` — случайный hex в приватном окружении, не в Git и не в
командной истории; hex избегает специальных символов в DATABASE_URL. Пока нет
управляемой секретной среды, значения переменных Docker доступны администратору
хоста. Production credentials и данные других проектов сюда не копировать.

API Dockerfile выполняет migrations и запускает существующий API, UI здесь не
раздается. UI необходимо собрать в отдельной среде, затем подготовить безопасную
доставку статических файлов; этот путь пока не реализован. Owner provisioning,
HTTPS nginx route, trusted proxy/rate limit, backup/restore и phone smoke должны
быть проверены отдельно до объявления готовности. Никаких default owner паролей.
Пределы памяти предварительные и не являются нагрузочным тестом. На VPS всего
1.1GiB доступной RAM по снимку, поэтому оценка влияния на портал обязательна.

## Обновление тестового стека до commit с preview боя (4371e4a)

Команды выполняет владелец; исполнитель на VPS не подключается. Порядок: read-only
проверка → backup БД и статики → API → статика → smoke → при сбое откат. Миграции
007/008 применяются автоматически при старте API (только добавляют таблицу и
колонку); откат кода их не удаляет и старому коду они не мешают. Портал, чужие
проекты, volumes, порты, firewall и nginx не изменяются. Точные команды — в
сообщении владельцу и в docs/HANDOFF.md не дублируются, чтобы не расходиться.

## Обновление одной командой (update.sh)

`infra/studio-test/update.sh <commit>` — запускает владелец от root из копии скрипта
нужного commit (`git show <commit>:infra/studio-test/update.sh > /tmp/ufagame-update.sh`).
Проверки до → pg_dump + старый commit + старая статика → API этого commit (миграции при
старте) → сборка Studio во временном контейнере → проверки после. Любой сбой после
переключения возвращает прежний commit, API и статику. Трогает только сервис `api`
проекта ufagame_s09_test и /srv/ufagame-test/studio.
