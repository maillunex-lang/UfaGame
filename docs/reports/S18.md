# S18 — локальная подготовка команд боя

Статус blocked: S17 не завершен. Добавлен исключительно локальный in-memory
прототип BattleSession: фиксирует battle_id/content_version, принимает ручную
команду на следующий шаг, проверяет последовательность, сторону, живого актера,
готовность/дистанцию и запоминает ack. Идентичный повтор возвращает тот же ack;
изменение команды с тем же seq, пропуск seq и просрочка отклоняются. При auto
основная способность активируется ядром; в manual только принятой командой.
Никаких WebSocket/API, авторизации игрока, долговременного хранения, наград или
клиентской выдачи результата нет. Это не production battle session.

`npm run check:battle`: 16 тестов passed, включая изменения будущего состояния,
повтор, порядок, просрочку, неверную сторону, диапазон/энергию, изоляцию снимка
и фиксированную версию контента. Это автоматические unit tests без сети и без
реальных игровых данных. Не реализованы события с сетевым sequence, reconnect и
восстановление pending-команд после процесса, политика потери связи, серверные
права/гонки, таймер реального времени, WebSocket и нагрузка. S18 blocked; нельзя
объявлять его завершенным или использовать как серверную сессию. Следующий шаг —
завершить S17 и отдельно реализовать защищенный транспорт и persistence.

## Разработка серверного потока

Состояние S17 сверено с main: локальный in-memory прототип был готов, полноценного
WebSocket не было. Добавлены предварительные контракты команд/кадров/снимка и
ADR 0017; исправлена проверка оглушения/перезарядки ручной способности. Создан
пошаговый обработчик с очередью до пяти шагов вперед, идемпотентностью seq,
лимитом команд, отдельным ack о постановке в очередь и результатом на шаге.
При отсутствии соединения принудительно включается авто; отклоняются запоздавшие
и неверные команды. Версия контента и seed закреплены.

Добавлены миграция 011, сохранение состояния и кадров в PostgreSQL, серверный
таймер и авторизованный WebSocket с ограничением размера/частоты сообщений и
коротким lease соединения. Запросы не содержат client result или наград.
Подготовлены реальные интеграционные тесты PostgreSQL/WebSocket на чужой доступ,
повтор, просрочку, переподключение, restart и версию контента. `npm run check`,
`npm run check:contracts`, `npm run check:battle` (36 passed), `npm run check:api`,
`npm run check:game` (Godot 4.6.3) и мобильный Chromium с mock API прошли локально.
Без доступа к локальной PostgreSQL интеграционные тесты в текущей среде еще не
выполнялись; требуются CI и исправление возможных ошибок, до этого S18 in_progress.

S18 не развернут на VPS и не проверен по настоящему интернету/на Android. Для
WebSocket через nginx потребуется отдельный подготовленный diff/rollback;
текущий /game/server/ не подтвержден для upgrade. Нагрузочный тест ограничений,
падения worker/БД и полная проверка безопасности еще не проведены. S19 не начат.

## Автоматические проверки локального сервиса

Создана отдельная временная PostgreSQL 17 на локальном Unix-сокете без TCP и
без доступа к VPS. Миграции 001–011 применены дважды. Полный набор integration
с этой БД, Chromium и настоящим Godot: 33 passed (до добавления отдельного теста
ограничения WebSocket); последние 5 S18 integration tests отдельно passed,
включая 401/404, кадры, ручную способность, дубликаты/конфликт/порядок,
дедлайн по часам БД, замену соединения, отзыв сессии, reconnect, restart,
восстановление 900 шагов offline и отсутствие наград. URL с токеном и входящее
сообщение сверх 2048 B отклоняются. `npm run check:battle`: 37 passed;
`npm run check`, `npm run check:studio:browser`, `npm run check:game` exit0.

Код размещается сначала в тестовой ветке, CI должен подтвердить финальные изменения
перед переносом в main. Внешний WSS через nginx, Android, многодневное хранение
кадров и нагрузка VPS не проверены. На VPS и в существующем портале изменений нет.
