# S15 — публикация контента и version pointer

Статус: done (тестовый канал). Commit — см. roadmap. ADR 0014, миграция 009.

Реализовано: неизменяемые версии и хранилище ресурсов по хешу (триггеры запрещают
UPDATE/DELETE), указатель канала `test` с ревизией, журнал релизов, preflight с
диффом/проблемами/предупреждениями, ручная публикация одной транзакцией, возврат
указателя, клиентская выдача целого совместимого комплекта и ресурсов по хешу.
Studio: секция «Публикация контента» — проверка, подтверждение, журнал, «Сделать
активной» для прежних версий.

Проверки (Node 24.22.1, PostgreSQL 16.15, Chromium):
- интеграция (реальная БД): нет версии → 404; preflight (403 без CSRF, 409 устаревшая
  ревизия, дифф, предупреждение); публикация и повтор request_id; клиент: bundle по
  схеме, ETag/304, blob по хешу с immutable cache, 400 без заголовка, 409
  INCOMPATIBLE_CLIENT с перечнем; NO_CHANGES; две конкурирующие публикации → 200 и 409;
  сбой вставки журнала (между подготовкой и фиксацией) → 500, версий не добавилось,
  указатель прежний; прямой SQL UPDATE/DELETE опубликованного отвергнут; возврат
  указателя: устаревшая ревизия 409, неизвестная версия 404, текущая 409, успешный
  возврат и повтор, клиент получает прежнюю версию; журнал и audit (3 записи).
- `npm run check` exit0; Chromium mobile (mock API): проверка, публикация с
  подтверждением, «уже опубликована».
- Полная интеграция: 26/27, провал только Godot (ENOENT в среде).

Не проверено: VPS (миграция 009 не применена), телефон, загрузка комплекта игрой
(S16), производительность при большом числе версий (журнал ограничен 100 записями).
Каналы, кроме `test`, и подпись клиентского манифеста доверенным pipeline — позже
(S47/S57).
