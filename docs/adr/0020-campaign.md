# ADR 0020: кампания, главы, боссы и награды за первую победу (S22)

Статус: принято. Capability `campaign.chapters.v1`.

- Новый вид контента `chapter`: `order` 1–999 (уникален), `stage_ids` 1–50 по порядку
  прохождения, необязательные `location_id` (район/город — карта главы), `description`,
  `proposed` (маршрут предварительный, пока владелец не выбрал окончательный).
  Этап может стоять только в одной главе. У `stage` новые `boss` и `rewards_first`
  (золото/самоцветы, 1–1 000 000, каждая валюта один раз, не больше 4 записей).
- Порядок кампании: главы по `order`, внутри — по `stage_ids`. Первый этап открыт;
  каждый следующий открывается после победы на предыдущем. Решает только сервер
  (`campaign_progress`, миграция 012). Этапы вне глав — тренировка: без прогресса и наград.
- Закрытый этап: `POST /v1/live-battles` → 409 (`STAGE_LOCKED`). Попытки бесплатны и
  неограниченны: поражение ничего не меняет и ничего не тратит (энергии попыток нет).
- Победа фиксируется в той же транзакции, что и итоговый шаг боя: вставка в
  `campaign_progress` с `ON CONFLICT DO NOTHING`; награда из закреплённой версии контента
  боя через журнал с ключом `campaign:first:<stage>:<currency>`. Повтор, дубль тика и гонка
  не платят второй раз (первичный ключ + уникальный ключ журнала).
- `GET /v1/campaign` (схема `campaign`): главы, этапы со статусом `cleared|open|locked`,
  наградами и `cleared_battle_id`. Клиент показывает награду только когда сервер вернул
  `cleared_battle_id` этого боя; клиент сам валюту не начисляет.
- Путь главы в Game строится по точкам этапов на карте (`stage.location_id` → координаты),
  если у каждого этапа своя точка; иначе — зигзаг сверху вниз. Всё меняется из Studio
  без нового APK в пределах этой capability; Game до v12 такой мир не примет.
- Откат: миграция только добавляет таблицу; старый API её игнорирует. Удаление
  прогресса не требуется при откате кода.
