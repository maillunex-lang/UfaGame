# ADR 0022: VIP и обучение, призыв, AFK-награды (S25/S27/S29)

Статус: принято. Capabilities `vip.v1`, `summon.v1`, `afk.v1`. Все числа — предложения
владельцу (`proposed`), меняются в Studio без нового APK.

## VIP и обучение (S25)
- Контент `vip` (одна таблица): уровни 1–20 с порогом очков (строго растут), текстом
  привилегий и привилегией `afk_hours` (дополнительные часы AFK сверх 12);
  `tutorial_points` (однократно за обучение, ≥ порога VIP 1), `daily_points`
  (возобновляемый бесплатный источник, раз в сутки по времени Уфы), `win_points` за
  любую победу с суточным пределом `win_points_daily_cap`.
- Очки — валюта `vip_points` в ledger; они только копятся (не тратятся). Уровень VIP
  вычисляется сервером из суммы очков и текущей таблицы, не хранится и не задаётся
  клиентом. Смена таблицы пересчитывает уровень от тех же очков (политика: очки
  неизменны, уровень — функция таблицы). Платные источники позже (S56) зачисляют те же
  очки через ledger с причиной покупки; привилегии зависят только от уровня, не от
  факта оплаты. Тестовые товары отделяются явно, вымышленных покупок нет.
- Достижимость без оплаты: проверка контракта — при `daily_points`>0 любой порог
  достижим за конечное число дней; Studio показывает «дней до уровня» бесплатно.
- Обучение — серверные шаги по фактическому состоянию: первая победа в кампании,
  повышение уровня героя, предмет на герое. Награда (`tutorial_points`) один раз по
  ключу ledger `tutorial:vip`; повтор ничего не даёт.

## Призыв (S27)
- Контент `summon_pool`: цена (валюта gold|gems), записи `{hero_id, weight, shards?}`
  (с `shards` выпадают осколки героя вместо героя), гарантия `{every, hero_ids}`: если
  `every−1` попыток подряд не дали героя из списка гарантии, следующая даёт его
  (равновероятно из списка), `shards_per_hero` — сколько осколков собирают героя.
  Шансы показывает сервер: вес/сумма весов. Неверные веса/ссылки — отказ контракта.
- RNG только серверный (`crypto.randomInt`). Попытка (1 или 10) — одна транзакция:
  списание цены, счётчик гарантии, выдача героев/осколков, запись результата с
  `request_id`; повтор того же `request_id` возвращает сохранённый результат.
- Счётчик гарантии хранится по `pool_id` и не сбрасывается при смене контента; если
  `every` уменьшили и счётчик уже не меньше `every−1`, следующая попытка гарантирована.
- Осколки — валюта `shard_<hero_id>`; сборка героя списывает `shards_per_hero` и выдаёт
  экземпляр в одной транзакции (ключ от request_id).

## AFK-награды (S29)
- Контент `afk`: доход в час `{currency, amount}` (gold, hero_exp, rank_material),
  прибавка за каждый пройденный этап кампании `stage_bonus_bp`. Базовый предел — 12 часов,
  сверху только VIP `afk_hours`.
- Время — только серверное (`clock_timestamp()` БД). Состояние: начало накопления,
  накопленные «единицы» (доход×мс) по валютам и текущая ставка с её версией.
- Смена ставки (новый пройденный этап, новая версия контента): прошлый отрезок
  закрывается по старой ставке до момента смены (для версии — время публикации версии),
  дальше действует новая. Прошлое не пересчитывается.
- Получение: накопленное округляется вниз, остаток единиц сохраняется; выплата через
  ledger с ключом получения; повтор `request_id` возвращает тот же ответ, параллельные
  получения сериализуются блокировкой игрока — второе ничего не выдаёт.
