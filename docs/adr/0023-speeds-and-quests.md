# ADR 0023: скорости боя и быстрый расчёт (S26), квесты (S30)

Статус: принято. Capabilities `battle.speed.v1`, `quests.v1`. Числа — предложения.

## Скорости и быстрый расчёт (S26)
- В таблице `vip`: `speed_x2_stages` (×2 после стольких пройденных этапов кампании),
  `speed_x4_level` (×4 с этого VIP, по умолчанию 4), `instant_level` (быстрый расчёт с этого
  VIP, по умолчанию 7). Без этих полей доступна только ×1 (как раньше).
- Скорость меняет только реальное время между шагами живого боя (100/50/25 мс); бой всегда
  900 шагов = 90 игровых секунд, тот же шаг ядра, те же правила авто. Команда `speed`
  идёт в общей очереди команд с `seq`; сервер проверяет право (прогресс/VIP) при приёме
  (409 `SPEED_NOT_ALLOWED`) и меняет такт с указанного шага. Кадр и снимок несут `speed`.
- Быстрый расчёт (`POST /v1/battles`) при заданном `instant_level`: только VIP ≥ уровня и
  только уже пройденный этап кампании (первое прохождение — только живым боем,
  409 `FIRST_CLEAR_REQUIRES_BATTLE`/`INSTANT_NOT_ALLOWED`). Результат считает сервер тем же
  ядром в режиме авто с серверным seed; клиент не присылает итог. Наград за первое
  прохождение быстрый расчёт не даёт (этап уже пройден).
- Проверено тестом ядра: живой бой в авто и быстрый расчёт с тем же setup/seed дают одинаковый
  итог и состояние.

## Квесты (S30)
- Контент `quest`: `period` (`daily` — сбрасывается в полночь по Уфе, `once` — достижение),
  `event` из фиксированного списка серверных событий (`battle_win`, `campaign_clear`,
  `hero_level_up`, `hero_rank_up`, `summon_pull`, `afk_claim`, `item_upgrade`), необязательный
  `stage_id` (условие для побед/прохождений), `target` 1–10000, награды (валюты, герои 0–3),
  `requires_quest_id` (серия: открывается после получения награды предыдущего).
- События записывает только сервер в той же транзакции, что и действие, с уникальным
  ключом события — одно событие учитывается один раз (повтор/гонка не удваивают).
- Прогресс хранится по периоду (`daily`: дата Уфы, `once`: пустая строка). Награду выдаёт
  сервер по своему состоянию (прогресс ≥ цели, период текущий, не получена, серия открыта);
  ledger-ключ от квеста и периода. Вчерашний дневной прогресс не получить (истёк).
- Квест со ссылкой на несуществующий этап/героя/квест или цикл серии — ошибка контракта:
  публикация блокируется; Studio не даёт удалить используемые объекты.
