# ADR 0013: ug-content/1 с ресурсами, импорт и экспорт черновика

Статус: принято (S12–S14). Заменяет предварительные решения ADR 0008 в части
replace/delete и ресурсов.

## Контракт пакета
- Пути: `operations.json`, `README.md`, `entities/**/*.json`, `resources/**/*.json`,
  `assets/**/*.png|wav` — только ASCII, без `..`, скрытых сегментов, обратных слешей,
  зарезервированных имен Windows; коллизии по регистру/NFC запрещены. Другие типы
  (js, gd, tscn, ogg, jpg, вложенные zip) не могут быть даже перечислены.
- Каждый файл, кроме manifest, перечислен ровно один раз с size/sha256; каждый
  `entities`/`resources` файл используется ровно одной операцией, каждый asset —
  ровно одним ресурсом. Неописанные и неиспользуемые файлы — отказ.
- Ресурс: операция `create` с `entity_type: resource` и метаданными
  `mod_resource` (id, file, license, loop, для PNG — scale/anchor/frames). Байты
  ресурса неизменяемы: тот же id с тем же SHA-256 — «без изменений», с другим — конфликт,
  который можно решить только оставлением существующего (новый ресурс — новый id).
- `replace`/`delete` несут `expected_sha256` = SHA-256 канонического JSON объекта
  (ключи отсортированы рекурсивно, без пробелов; `canonical.mjs`). У сущностей в
  черновике нет собственных ревизий, хеш однозначно фиксирует «какую версию я менял».
  `expected_revision` из ADR 0008 удален. `compensation_rule_id` для delete допустим,
  но в черновике не применяется: компенсации относятся к опубликованному контенту (S46).
- Зависимости между пакетами (`dependencies`) пока отклоняются явно.

## Проверка (карантин)
`inspectArchive` читает ZIP только в память (лимиты: архив 8 МиБ, распаковано 32 МиБ,
файл 8 МиБ, 1000 записей, сжатие ≤100, только stored/deflate, без шифрования и
symlink/спецфайлов), ничего не пишет на диск и не исполняет. Ошибки — `PackageError`
с кодом, файлом и полем, API отдает их как `422` `CODE:file:field`.

## План и применение
`planImport` без записи строит отчет по каждому ресурсу/объекту: create, replace,
delete, unchanged, conflict (BASE_MISMATCH, ENTITY_EXISTS, ENTITY_STALE,
ENTITY_MISSING, RESOURCE_EXISTS) с диффом полей; решения владельца — `package` или
`draft` по ключу `entity:<id>`/`resource:<id>`/`base`. Новые ресурсы проверяются
изолированным декодером S11. Итог проверяется схемой, ссылками между объектами и
типами ресурсов.

API: `POST /admin/v1/drafts/:id/import/preflight` (только чтение) и
`POST .../import/apply` — одна транзакция: блокировки владельца и черновика,
проверка ревизии, квоты ресурсов, вставка ресурсов, обновление черновика (+1 ревизия)
и один audit `draft.import`; повтор с тем же request_id возвращает прежний результат,
другой payload с тем же request_id — 409; любая ошибка откатывает все. Импорт не
публикует контент. Экспорт: `GET /admin/v1/drafts/:id/export[?ids=a,b]` — сохраненная
версия, выбранные объекты с транзитивными зависимостями и ресурсами, детерминированный
ZIP с create-операциями. Android Studio v14 разрешает загрузку этого адреса с `?ids=`.
