# ADR 0011: предварительное хранение PNG ресурсов владельца

Контракт первого среза: только ограниченный PNG с явными метаданными лицензии,
масштаба, точки привязки, кадров и loop. Владелец загружает JSON/base64 через
admin API с проверкой session, Origin и CSRF до чтения тела. PNG проверяется
ограниченным дочерним Node процессом, который не является полноценным sandbox ОС.
Максимум 8 МиБ на файл, 128 объектов, 32 МиБ на тестовую БД; PNG, проверка
декодирования, тип и размеры не определяются только расширением. Создание атомарно
с audit, request_id и блокировкой квоты; существующий id не перезаписывается.
Превью чтением image/png доступно только активному владельцу. Ни удаление,
ни публикация, ни импорт ZIP здесь не реализованы. Для других форматов и
промышленной изоляции нужны отдельные изменения и проверки.

Дополнение: метаданные кадров редактируются owner PATCH с expected_revision,
конфликтом 409 и audit в той же транзакции. Для ранее примененной миграции 007
добавлена отдельная миграция 008 с revision: изменять уже опубликованную
миграцию нельзя. Перенастройка не меняет исходные байты. Реестр и preview в
редакторе остаются ограниченным PNG срезом S11.
