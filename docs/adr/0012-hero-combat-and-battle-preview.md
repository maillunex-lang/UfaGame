# ADR 0012: боевые параметры героя и серверный preview боя в Studio

Статус: принято для тестового среза S17/S20. Не является публикацией контента (S15)
и не подключает бой к Game (S18/S19).

## Контракт контента

- `hero.data.combat` (необязательный, `additionalProperties:false`): `hp` 1..1e6,
  `attack`/`defense` 0..1e6, `speed` 0..5000 ед./шаг, `range` 0..20000,
  `attack_interval_ms` 100..90000 кратно 100, `energy_start` 0..1000,
  `energy_per_second` 0..10000 кратно 10, `energy_per_attack` 0..1000.
- `ability.data.energy_cost` (необязательный, 1..1000) — стоимость основной способности.
- Новая capability `battle.combat.v1`. Контент, где есть `combat` или `energy_cost`,
  обязан объявить ее в `required_capabilities`, иначе `validate('content')` отказывает.
  Старые клиенты без capability получают явную несовместимость, а не молча
  отбрасывают поля. Studio добавляет/убирает capability автоматически.
- Существующие черновики без этих полей остаются валидными (поля необязательные).

## Компиляция в внутренний снимок v2

`packages/battle-core/compile.mjs` переводит сохраненный черновик в снимок
`auto.schema.json` (ADR 0009):

- слот = позиция в списке (0–1 впереди, 2–4 сзади), 1–5 героев на сторону;
  противник — список героев или `stage.enemy_hero_ids`; id бойцов `atk_N`/`def_N`,
  поэтому один герой может стоять в нескольких слотах;
- `ability_ids[0]` — основная способность (энергия, cost = `energy_cost` или 1000);
  остальные — авто-способности с `interval_steps = max(1, ceil(cooldown_ms/100))`,
  больше 900 шагов — ошибка `ABILITY_COOLDOWN_TOO_LONG`. `cooldown_ms` основной
  способности используется как `cooldown_steps` с ADR 0016;
- `interval_steps = attack_interval_ms/100`, `energy_per_step = energy_per_second/10`;
- фракции — только встречающиеся в бою (не больше 6), ссылки преимущества
  обрезаются до участников; `advantage_bp` временно фиксирован 12000 (x1.2) до
  появления глобальных правил баланса в контенте;
- ошибки — `BattleCompileError{code, entity_id}`: `HERO_COMBAT_MISSING`,
  `UNKNOWN_HERO/ABILITY/FACTION/STAGE`, `INVALID_TEAM_SIZE`, `TOO_MANY_FACTIONS`,
  `ABILITY_COOLDOWN_TOO_LONG`, `INVALID_REQUEST`.

`runAutoBattle` прогоняет бой до результата (максимум 900 шагов), возвращает кадры
каждые 500 мс (+начало/конец, ≤182), первые 500 событий без движения, итоги по
бойцу и SHA-256 полного упорядоченного журнала (включая движение) для проверки
детерминизма/повтора.

## API

`POST /admin/v1/drafts/:id/battle-preview` — только активный владелец, Origin и
CSRF, лимит 20/мин. Тело `battle_preview_request` (`expected_revision`,
`attacker_hero_ids`, `defender_hero_ids` или `stage_id`, `seed`); неизвестные поля,
в том числе попытка передать результат, — 400. Сервер читает сохраненную версию
черновика: другая ревизия — 409, черновик не найден — 404, ошибка сборки боя —
422 с `error.code=INVALID_REQUEST` и `error.message=<CODE>[:entity_id]` (список кодов
ошибок контракта не расширялся). Ответ — `battle_preview`. Запрос ничего не пишет
в БД и не создает audit: это проверка, без наград, рейтинга и прогресса.

Бой считается синхронно в процессе API. Локальный замер худшего проверенного
случая 5×5/900 шагов — десятки миллисекунд; на 1,9 ГиБ VPS не измерялся. При
росте нагрузки перенести расчет в worker/child process с лимитом времени.

## Откат

Миграций нет. Откат — revert commit; черновики с `combat` после отката перестанут
проходить старую схему, поэтому перед откатом удалить эти поля из черновиков или
оставить новую схему.
