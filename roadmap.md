# roadmap.md - единый статус UfaGame
Дата: 2026-11-02, Asia/Yekaterinburg.
Опрос завершен: 55/55. Подготовлены документы и промпты. **Есть технические Game/Studio APK, локальный API/PostgreSQL и веб-интерфейс Studio. S04 принят после подтверждения резервной копии ключей; S09 ждет проверки на телефоне. VPS частично обследован владельцем, развертывание не выполнялось. Игровые системы и полный редактор еще не реализованы.**
GitHub: публичный https://github.com/maillunex-lang/UfaGame; доступ на запись проверен. Результат публикации документов фиксируется в GITHUB_PUBLICATION.md, а не подменяет готовность S02.

## Статусы и порядок
todo - не начато; in_progress - реализуется; blocked - конкретный блокер; done - реализовано и проверено.
S01–S09 done; S10, S11, S17 и S51 in_progress; S52 blocked; остальные этапы — по таблице. Подготовка промпта не означает выполнение этапа.
S01–S24: постепенный технический срез; S01–S53: первая рабочая версия с выбранными базовыми режимами; S54–S57: полнота/проверки/публичный запуск; S58–S60: поздние расширения.
План сложного проекта не является гарантией сроков. Каждый этап при необходимости дробится на подзадачи с сохранением зависимостей и приемки.
Частично доступную работу продолжать независимо, но недоступную проверку не отмечать done.

## Подробные этапы
### S01. Проверка стека и технический прототип
Зависимости: нет.
Задача: Проверить официальную документацию, доступность Godot/SDK/JDK/Node/PostgreSQL. Собрать минимальный Android-прототип, проверить постоянный каталог ресурсов и проигрывание серверных событий. Зафиксировать версии, min Android, ABI, package IDs, размерный бюджет и ADR.
Готовность: Есть воспроизводимые команды, lock/version-файлы, отчет размера APK и список непроверенного. Решение о стеке основано на прототипе, не на обещании.
Проверки: Чистая сборка; измерение APK; запуск на устройстве либо явный blocked для устройства.
Промпт: [S01](prompts/stages/S01.md).

### S02. Monorepo, GitHub и правила работы
Зависимости: S01.
Задача: Проверить актуальный maillunex-lang/UfaGame, сохранить документы, создать каталоги приложений/сервисов/пакетов, команды запуска, CI, .env.example и правила секретов. Не перезаписывать изменившуюся ветку.
Готовность: Чистый checkout воспроизводит проверки. Документы текущего опроса актуальны, старые противоречия не используются. Публичность и текущий commit подтверждены.
Проверки: Lint/format, проверка случайных секретов, команды начального запуска.
Промпт: [S02](prompts/stages/S02.md).

### S03. Контракты API и модель контента
Зависимости: S02.
Задача: Описать версии API/схем, stable IDs, сущности, capabilities, ошибки, currency ledger, battle snapshot и формат событий. Создать JSON Schema и контрактные примеры.
Готовность: Сервер/клиент/редактор используют один контракт. Неизвестные поля и типы обрабатываются явно. Есть правила миграций и совместимости.
Проверки: Валидные/невалидные fixtures, сериализация, несовместимая capability.
Промпт: [S03](prompts/stages/S03.md).

### S04. Сборка и подпись Android
Зависимости: S03.
Задача: Настроить воспроизводимую сборку Game и Studio, release signing без секретов в git, versionCode и отчеты hash/certificate/size. Предусмотреть приватное резервирование ключа.
Готовность: Оба минимальных APK собираются выбранным toolchain. Размер игры измерен относительно 95 МБ; подпись постоянна, ключ не публичный.
Проверки: Повторная сборка; анализ подписи/ABI; установка новой версии поверх старой при доступном устройстве.
Промпт: [S04](prompts/stages/S04.md).

### S05. База, API и транзакционный ledger
Зависимости: S03.
Задача: Создать PostgreSQL миграции, API health, журнал ресурсов, idempotency keys, транзакции и фоновые задания с lease. Задать лимиты и конфигурацию окружений.
Готовность: Повтор запроса не дублирует награду. Конкурентные траты не создают отрицательный баланс. Миграции воспроизводимы.
Проверки: Integration: rollback транзакции, гонка траты, повтор idempotency key, health.
Промпт: [S05](prompts/stages/S05.md).

### S06. Гостевой аккаунт и сессии
Зависимости: S05.
Задача: Реализовать создание гостя, защищенный токен, refresh/revoke, загрузку прогресса. Device ID не является секретом. Сохранять учетные данные безопасно на Android.
Готовность: Перезапуск сохраняет гостевой прогресс, чужой аккаунт недоступен, отозванная сессия не действует.
Проверки: Два гостя, истечение/отзыв токена, повтор создания, потеря сети.
Промпт: [S06](prompts/stages/S06.md).

### S07. Привязка логина и восстановление кодом
Зависимости: S06.
Задача: Добавить уникальный логин/пароль, проверенный password hash, криптографический recovery code, хранение его хеша, ротацию после восстановления и rate limits.
Готовность: Привязка сохраняет тот же player_id. Код одноразовый, повтор не работает, пароли/коды не логируются. Игроку объяснено сохранение кода.
Проверки: Гонки одинаковых логинов, неверный код, повтор восстановления, отзыв прежних сессий.
Промпт: [S07](prompts/stages/S07.md).

### S08. Владелец комбайна и аудит
Зависимости: S07.
Задача: Создать один аккаунт владельца, отдельную авторизацию административных API, аудит до/после и защищенную сессию. Решить CSRF и безопасное хранение сессии.
Готовность: Игрок не может вызвать admin API; каждое изменение имеет actor/reason/request_id. Нет публичного пароля по умолчанию.
Проверки: Запрет player token, завершение сессии, CSRF/authorization проверки.
Промпт: [S08](prompts/stages/S08.md).

### S09. Каркас веб-комбайна и черновики
Зависимости: S08.
Задача: Создать русский мобильный интерфейс, навигацию редакторов, формы и серверные черновики с optimistic concurrency и diff.
Готовность: Черновик переживает перезагрузку и не меняет опубликованную игру. Конфликт редактирования показан явно.
Проверки: Сохранение/восстановление, два параллельных изменения, проверка с телефона.
Промпт: [S09](prompts/stages/S09.md).

### S10. Game Studio Android APK
Зависимости: S04, S09.
Задача: Сделать Kotlin WebView-оболочку общего HTTPS-комбайна, file chooser/import/export, back navigation, обработку ошибок и сессии, ограниченный origin.
Готовность: Владелец загружает/скачивает файлы с Android. Произвольные сайты не получают мост к приложению. APK подписан.
Проверки: Сессия после перезапуска, отказ в выборе файла, чужой origin, ZIP import/export UI.
Промпт: [S10](prompts/stages/S10.md).

### S11. Реестр ресурсов и анимации
Зависимости: S03, S09.
Задача: Загрузка изображений/атласов/кадров/аудио, хеши, лимиты размеров, метаданные лицензий, настройка масштаба и точек крепления, preview.
Готовность: Готовый ресурс виден в редакторе с корректными кадрами и ссылками. Объемы ограничены, тип не определяется только расширением.
Проверки: Поврежденное изображение, чрезмерный размер, отсутствующий кадр, цикл анимации.
Промпт: [S11](prompts/stages/S11.md).

### S12. Контракт ZIP-модификации
Зависимости: S03, S11.
Задача: Перенести MODDING_SPEC в строгие схемы manifest/operations, версии capabilities, file inventory/hash, base revision и документы генерации для внешнего ИИ.
Готовность: Примеры проходят схемы; неизвестные операции не игнорируются, запрещенные файлы не допустимы. Статический пример не выдается за runtime-проверку.
Проверки: Схемы всех примеров и негативные fixtures.
Промпт: [S12](prompts/stages/S12.md).

### S13. Защищенный валидатор ZIP
Зависимости: S12.
Задача: Проверять пути, symlinks, дубликаты, Unicode/case коллизии, zip bomb/лимиты, hash, ссылки, capabilities и отсутствие кода. Распаковывать только в карантин.
Готовность: Нельзя выйти из каталога, исполнить скрипт, переполнить диск в пределах заявленного бюджета. Ошибки объясняют файл/поле.
Проверки: Traversal, absolute path, symlink, duplicate entry, bomb limits, неверный hash, неизвестная schema.
Промпт: [S13](prompts/stages/S13.md).

### S14. Импорт, экспорт и разрешение конфликтов
Зависимости: S09, S13.
Задача: Добавить ZIP UI, diff по объектам/полям, base revision, ручное разрешение конфликтов и атомарное изменение черновика. Экспортировать выбранный набор с зависимостями.
Готовность: Отмена/ошибка не меняют черновик частично. Export-import воспроизводит выбранные определения. Импорт сам не публикует.
Проверки: Устаревшая база, конфликт ссылки, повтор импорта, отмена в середине.
Промпт: [S14](prompts/stages/S14.md).

### S15. Публикация контента и version pointer
Зависимости: S14.
Задача: Создать immutable content versions, preflight, preview, ручное publish, совместимость и rollback указателя. Отдельно планировать изменения состояния.
Готовность: Неполная версия не становится активной, клиент получает целый совместимый комплект. Есть журнал release и rollback.
Проверки: Сбой между prepare/commit, конкурирующая публикация, несовместимый клиент, возврат указателя.
Промпт: [S15](prompts/stages/S15.md).

### S16. Game: вход, загрузчик и постоянные ресурсы
Зависимости: S04, S06, S15.
Задача: Сделать русский вход/обучение-загрузчик, манифест ресурсов, storage по hash в постоянном каталоге, .part/resume, первичный пакет и Скачать все.
Готовность: Неизменившийся файл не скачивается повторно после перезапуска. Поврежденный заменяется, незавершенный не активируется.
Проверки: Оборванная загрузка, нет места, неверный hash, перезапуск, трассировка повторного запуска без скачивания ресурса.
Промпт: [S16](prompts/stages/S16.md).

### S17. Серверное ядро автобоя
Зависимости: S05, S03.
Задача: Реализовать fixed-step battle-core, 5 против 5 с 2+3, движение/цели/энергию/переменные способности/фракции. 90 секунд игрового времени, таймаут - поражение атакующего.
Готовность: Один seed/snapshot дает повторяемый результат. Нет клиентской выдачи победы. Формулы, порядок событий и бюджет выполнения документированы.
Проверки: Детерминизм, ничья/одновременная смерть, таймаут, неизвестный эффект, бесконечный цикл.
Промпт: [S17](prompts/stages/S17.md).

### S18. Поток боя и ручные команды
Зависимости: S06, S17.
Задача: WebSocket battle session, серверный шаг, команды основной способности по портрету, авто, sequence/ack, reconnect и политика при обрыве.
Готовность: Ручная команда меняет еще не рассчитанное состояние; дубликат не применяет способность дважды. Версия контента закреплена.
Проверки: Лаг, повтор/перестановка/просроченная команда, переподключение, обновление контента в бою.
Промпт: [S18](prompts/stages/S18.md).

### S19. Визуализация боя в Game
Зависимости: S11, S16, S18.
Задача: Отрисовать 2D бой, портреты, энергию/здоровье, движение и эффекты, переключение авто. Серверные события связывать с анимациями.
Готовность: Клиент показывает верный порядок и итог, не теряет события при ускорении/переподключении. Вертикальный UI удобен на телефоне.
Проверки: Android сценарий бой/команда/сеть; сравнение event log с показанным результатом.
Промпт: [S19](prompts/stages/S19.md).

### S20. Редакторы героев, врагов и способностей
Зависимости: S09, S17, S19.
Задача: Создать CRUD героев/врагов/фракций/навыков и граф готовых условий/действий с лимитами. Настройка основной способности и индивидуального набора.
Готовность: Герой из редактора/ZIP появляется и корректно действует в игре после публикации; неподдерживаемый блок отклоняется.
Проверки: Создание нового героя, изменение цели/энергии, удаленная ссылка, preview боя.
Промпт: [S20](prompts/stages/S20.md).

### S21. Геоданные и иерархия Башкортостана
Зависимости: S11, S15.
Задача: Выбрать допустимый источник географии, зафиксировать актуальность/атрибуцию, создать иерархию республика–район/город–точка, проекцию и художественные слои.
Готовность: Координаты/названия проверены по источникам. Карта редактируема, художественное изображение не выдается за точные геоданные.
Проверки: Связи и координаты, навигация уровней, пропавшая точка, источники/лицензии.
Промпт: [S21](prompts/stages/S21.md).

### S22. Кампания, главы и боссы
