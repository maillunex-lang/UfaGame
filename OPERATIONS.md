# Сборка, GitHub и VPS
## Сборка и релизы
Точные команды появятся на S01/S04/S10 и фиксируются в документах вместе с версиями. Не писать команды как уже проверенные, если сборка не выполнялась.
Game и Studio имеют разные package IDs и ключи либо явную документированную политику. Для каждой игры постоянный ключ между версиями; versionCode растет.
APK, hash, подпись, версия контракта и changelog прикладываются к GitHub Releases; бинарники не раздувают git-history. Сайт ссылается на нужный release asset. Signing keystore и пароли только в защищенном хранилище/CI secrets, приватная резервная копия.
CI не получает production-SSH для произвольных непроверенных pull requests. Разрешения workflow минимальные; публикацию готовых артефактов ограничить доверенным release flow.

## Инвентаризация VPS
До установки: ОС/ядро, CPU/RAM/swap, свободный диск/inodes, нагрузка, процессы, systemd services, listening ports, Docker networks/volumes, reverse proxy, сертификаты и планировщики.
Сохранить отчет без секретов и базовые health-check существующих проектов. Не выводить .env, приватные ключи, дампы и личные сообщения.
Предоставленный SSH host key сверить доверенным способом; не отключать проверку host key ради удобства.
Не выполнять global docker prune, не менять существующие публикации портов, не сбрасывать firewall, не перезапускать сервер.
Выбрать незанятые loopback-порты после проверки, а не жестко объявлять 80/443/5432 свободными.
Изоляция: отдельные каталоги, compose project names, DB users/databases, сети, volumes, env; test и prod с разными секретами и данными. Production-данные не копировать в test без обезличивания.
БД без публичного порта. Ресурсные лимиты, ротация логов, пул соединений, health-check. Общий reverse proxy: diff, config test и точечный reload только после проверки.
После развертывания повторить базовые проверки чужих проектов. Если регресс - откатить только собственные изменения.

## Копии и восстановление
Ежедневно и перед миграциями/массовой компенсацией/опасными изменениями. Данные БД, контент, конфигурация и список версий должны образовать согласованный checkpoint.
Копии вне публичного web-root, ограниченные права; защита секретов. План удаления старых копий и дисковый резерв, отчет о сбое.
Восстановить в отдельную пустую БД/каталог и проверить вход, инвентарь, version pointer, ledger и ресурсы. Наличие файла архива не означает успешное восстановление.
Копии на VPS не спасают от потери VPS. Внешние копии - S60, не включать молча.

## Релиз и откат
Зафиксировать commit, миграции, content_version, APK/versionCode, API compatibility, backup ID.
Развернуть в test → проверки → запланировать prod; держать предыдущий образ и ресурсы.
Откат бинарного приложения/контента и откат состояния игроков - разные операции. Не откатывать БД поверх уже совершенных покупок без плана сверки.
Наблюдаемость: ошибки, latency, очередь, бои, реальные онлайны отдельно от жителей, диск, резервные копии; журналы без паролей/кодов и лишних персональных данных.
