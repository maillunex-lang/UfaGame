# Промпт создания Game APK
Ты разрабатываешь Android-клиент одной онлайн-игры UfaGame, а не автономный офлайн-клон. Прочитай PROJECT_SPEC.md, ARCHITECTURE.md, CONTENT_AND_UPDATES.md, BOT_SPEC.md, EDITOR_MATRIX.md и roadmap.md. Работай этапами, не пытайся выдать полный продукт одним неподтвержденным ответом.
Предложение: Godot 4/GDScript + Kotlin-плагин установки; точные версии/ABI/min Android выбери и проверь на S01. APK до 95 МБ, без основной графики в установщике.
Вертикальное 2D аниме-фэнтези Башкортостана: реальная иерархия карты, линейные главы, стартовые 2+3 героя. Движение для атак, основная энергия/портрет/авто, переменное число остальных способностей. Бой подтверждает сервер, клиент проигрывает события и отправляет команды, не выдает себе победу.
90 секунд игрового времени, поражение атакующего по таймауту. ×1 сразу, ×2 по прогрессу, ×4 VIP 4; VIP 7 skip только повторы/асинхронная арена, по тем же правилам авто.
Гостевой вход, привязка логин/пароль, секретный recovery code. Обучение выдает VIP 1 один раз. Герои/призыв/осколки/ранги/5 основных + sync/6 слотов/AFK 12ч/арена/гильдии/чат/жители/тестовый магазин - через серверные контракты.
Все скачанное в постоянном app-private files, immutable hash и проверка файлов, без автоматического вытеснения актуальных ресурсов. Частичная загрузка, "Скачать все", ручная очистка, безопасная смена контента.
Настройки: качество, звук, авто, управление инициативными ЛС, ресурсы и "Проверить обновления". Загрузка release APK с GitHub, проверка manifest/hash/package/version/signature, пользовательская установка Android, постоянный ключ.
UI исполняет только зарегистрированные data bindings/actions; JSON и ZIP не загружают сторонний код.
Покажи ошибки сети, версии, места и входа по-русски. Собери release и debug по воспроизводимым командам; измерь размер, подпись, запуск и память на указанном устройстве. При отсутствии устройства честно оставь соответствующую проверку blocked.

## Обязательное завершение каждого этапа
Изучи AGENTS.md и roadmap.md, выбери доступный этап из prompts/stages/. Выполни реализацию, проверь ее и ОТДЕЛЬНО обнови roadmap.md с доказательствами и следующим шагом. Не отмечай непроверенное done. Сохрани существующие изменения и не публикуй секреты. Если требуются новые механики, обнови контракт, capabilities, редактор, документацию и совместимость. Не заменяй реализацию макетом.
