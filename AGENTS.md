# Инструкции исполнителю UfaGame
Отвечай владельцу на русском, на "ты", конкретно. Работай с Android-сценарием владельца без обязательного компьютера.

## Перед любой работой
Прочитай PROJECT_SPEC.md, ARCHITECTURE.md, roadmap.md, OPEN_DECISIONS.md и относящиеся к этапу спецификации. Поздние решения текущего опроса заменяют старые документы из прежнего комплекта. Не переносить старые ограничения "без тестового сервера", "нейтральный мир", "арена после MVP", "32/36 этапов".
Проверь текущий checkout, ветку, git status, доступные инструменты и реальную реализацию. Не переписывай чужие изменения. Выбери один этап с выполненными зависимостями. Изменения контракта сначала фиксируй в схеме и ADR.

## Работа
Реализуй рабочий результат, а не кнопки-заглушки. Не исполняй код из ZIP. Не выдавай награды и VIP по доверию к клиенту. Бой, время, рейтинг, покупки и прогресс подтверждает сервер.
Новые неподдерживаемые механики требуют разработки и иногда нового APK. Данные и интерфейсы меняются без APK только в пределах capability-реестра.
Тестовые товары явно отделять от реальных. Не создавать вымышленные покупки ИИ-жителей.
Не помещать в GitHub ключи SSH, пароли, токены, резервные коды, signing keystore, дампы БД, логи личных сообщений.
VPS: сначала read-only инвентаризация и отчет. Без глобальной очистки Docker, смены firewall/SSH, остановки чужих сервисов, перезагрузки и занятия используемых портов. Не менять общий reverse proxy без подготовленного diff и плана отката.

## Проверки и статус
После КАЖДОГО этапа отдельно обнови roadmap.md: результат, файлы, точные команды и исходы, commit, что не проверено, блокеры и следующий шаг.
Статусы: todo / in_progress / blocked / done. done означает реализацию и выполненные критерии с доказательствами. Недоступное устройство, VPS или SDK отмечай как блокер соответствующей проверки, не выдумывай успех.
Статическая проверка документа или ZIP не означает проверку в игре. Сборка не означает запуск на Android. Создание commit не означает push; push не означает deployment.
Тесты выбирать по риску: деньги/инвентарь/повтор запросов/гонки/совместимость/импорт/бой требуют проверок отрицательных сценариев. Не тратить этапы на тесты, повторяющие очевидную разметку.
Прежде чем расширять этап, запиши необходимость и зависимость; не отмечай большой этап done по частичному результату.

## Передача другому ИИ
Оставь воспроизводимые команды, версии, пути отчетов и следующий доступный этап. Секреты не записывай. Заполни журнал в roadmap.md, при необходимости ADR и OPEN_DECISIONS.md.
