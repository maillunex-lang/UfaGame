# Промпт создания Game Studio web + APK
Разработай комбайн для одной игры по PROJECT_SPEC.md, EDITOR_MATRIX.md, MODDING_SPEC.md, BOT_SPEC.md и roadmap.md. Предложение React/TypeScript и отдельная Kotlin WebView-оболочка для того же HTTPS-интерфейса. Точные версии зафиксировать после проверки.
Один владелец, защищенная сессия, серверная авторизация каждого действия, аудит. Комбайн удобен с Android: touch targets, формы без обязательного hover, масштабирование карт/макетов, сохранение черновика. Предложение обеих ориентаций требует проверки, не считать отдельным решением владельца.
Реализовать редакторы всех строк матрицы по этапам: контент/герои/способности/бой/фракции/карты/сюжет/прогресс/экипировка/экономика/события/VIP/магазин/арена/гильдии/жители/игроки.
UI-builder готовых компонентов: дерево, вложенность, anchors, bindings, свойства, undo/redo в черновике, предпросмотр размеров. Графика готовая: загрузка, атласы, кадры, точки крепления, preview; без встроенной генерации.
ZIP: загрузить → карантин → строгая проверка → diff/конфликты → изменение черновика. Никакого исполнения кода. Неизвестная capability дает отчет и задачу разработки.
Публикация только вручную после проверки и предпросмотра. Удаление с зависимостями и однократной компенсацией по заранее настроенному правилу; без правила блокировать. Rollback не должен молча отменять реальные покупки.
Для жителей: 10–30 адаптивно, профили/память/шаблоны/триггеры/ЛС/стили/отметка в профиле/VIP 1–7, журнал и стоп-кнопка.
Android-оболочка: только разрешенный HTTPS origin, отсутствие произвольного JS bridge, загрузка/выгрузка ZIP через безопасные системные механизмы, обработка файла/назад/ошибок/повторного входа. Секреты не в APK.
Приемка требует, чтобы объект из редактора реально заработал в игре после публикации, и тот же объект можно было обновить ZIP. Наличие формы без runtime-поведения недостаточно.

## Обязательное завершение каждого этапа
Изучи AGENTS.md и roadmap.md, выбери доступный этап из prompts/stages/. Выполни реализацию, проверь ее и ОТДЕЛЬНО обнови roadmap.md с доказательствами и следующим шагом. Не отмечай непроверенное done. Сохрани существующие изменения и не публикуй секреты. Если требуются новые механики, обнови контракт, capabilities, редактор, документацию и совместимость. Не заменяй реализацию макетом.
